# Build a Community-Driven GPX Route Sharing Platform Using Rust

## 1. Project Overview

Help me design and build a **public GPX route-sharing platform**, initially focused on cycling routes but designed to support other outdoor activities in the future.

The idea comes from my personal need to store, manage, and share GPX routes from my cycling activities. However, I want to make the platform accessible to everyone, allowing users to discover, upload, manage, and share interesting or unique routes they have explored.

My main inspirations are:

- **CariRute:** https://gpx.ai.id/
- **Komoot:** https://www.komoot.com/

I want the platform to provide functionality similar to CariRute for the initial MVP, while taking inspiration from Komoot's map visualization, route presentation, and overall user experience.

However, **I do not want to build a full social media platform like Komoot**, at least not initially.

The main focus should be:

- Discovering interesting cycling routes
- Sharing personal GPX routes with the community
- Displaying routes on interactive maps
- Providing useful route information
- Allowing users to download GPX files
- Maintaining public user profiles
- Creating a pleasant and intuitive user experience

The platform should be lightweight, performant, maintainable, and expandable.

- **Rust** as the primary programming language

**Do not force an entirely Rust-based implementation if doing so introduces unnecessary complexity.**

## 3. Core Features — MVP

### 3.1 User Authentication and Profiles

Users should be able to register, authenticate, and manage their accounts.

Required functionality:

- User registration and login
- Secure authentication
- Email verification
- User profile management
- Unique public username
- Profile picture
- Short biography
- Public list of uploaded routes
- Account settings

Each user should have a public profile accessible through a shareable URL.

Example:

`/users/username`

### Verified Profiles

The platform should distinguish between:

- **Email-verified users:** Users who have verified their email addresses
- **Verified contributors:** Users manually approved by administrators as trusted route contributors

Verified contributors may receive a visible verification badge.

For the MVP, contributor verification can be handled manually by administrators.

Do not automatically grant a trusted-contributor badge just because someone has verified their email.

### 3.2 Route Management — CRUD

Authenticated users should be able to create, view, update, and delete their own routes.

Each route should contain:

- Route title
- Short description
- GPX file
- Route category
- Cycling type
- Location or region
- Country
- Distance
- Elevation gain and loss, when available
- Estimated or recorded duration, when available
- Difficulty level
- Route cover image (optional)
- Additional photos (optional)
- Route tags
- Visibility status: public, unlisted, or private
- Creation and update timestamps
- Route author

Suggested cycling types:

- Road Cycling
- Gravel Cycling
- Mountain Biking
- Bike Touring
- Bikepacking
- Urban Cycling
- Mixed Terrain

The classification should be designed so other activities, such as hiking or trail running, can be introduced later.

### 3.3 GPX Upload and Processing

Allow users to upload GPX files directly.

The application should:

1. Validate the uploaded GPX file.
2. Parse its tracks, routes, and geographic coordinates.
3. Extract available metadata.
4. Calculate total distance based on route geometry.
5. Calculate elevation statistics when elevation data is available.
6. Extract duration when suitable timestamp data exists.
7. Generate an appropriate map preview.
8. Store the original GPX file.
9. Persist the extracted route metadata in the database.

The system must handle incomplete or malformed GPX files gracefully.

For example:

- Missing elevation data should not cause upload failure.
- Missing timestamps should not produce invented duration statistics.
- Multiple track segments should be handled correctly.
- Route distance should be calculated without incorrectly connecting unrelated track segments.

Do not invent metrics that cannot be derived reliably from the GPX file.

Implement file size limits, secure file handling, and basic duplicate detection.

### 3.4 Interactive Route Visualization

**The interactive map is one of the most important features of this platform.**

Users should be able to inspect routes directly from the browser.

The map should support:

- Zooming
- Panning
- Route polyline rendering
- Start and finish markers
- Automatic map bounds fitting
- Fullscreen map view
- Responsive interaction on mobile devices
- Alternative map styles, where supported

If elevation data is available, display an interactive elevation profile.

Ideally, users should be able to hover over an elevation chart and see the corresponding position on the route.

The map should feel smooth and responsive, even when handling relatively large GPX files.

Evaluate whether route geometry should be simplified for rendering while preserving the original GPX file for downloads.

### 3.5 Route Discovery

Create a public route discovery page where users can browse routes uploaded by the community.

The discovery page should have:

- Search by route title
- Search or filtering by region
- Filtering by cycling type
- Filtering by difficulty
- Filtering by distance range
- Sorting by newest or popularity
- Pagination

Each route should have a visually appealing preview card displaying:

- Route preview map or cover image
- Route title
- Region
- Distance
- Elevation gain, if available
- Cycling category
- Author information
- Download count, if tracked

Prioritize discoverability rather than social engagement.

### 3.6 Route Detail Page

Each public route should have its own dedicated page with a shareable URL.

Example:

`/routes/taipei-riverside-loop`

The page should display:

- Route title
- Description
- Interactive map
- Route statistics
- Elevation profile, when available
- Cycling category
- Region
- Route photos
- Author information
- GPX download button
- Share button

Use human-readable, unique route slugs.

The page should also include appropriate SEO metadata and Open Graph information for link sharing.

### 3.7 GPX Download and Sharing

Public routes should be downloadable without requiring an account.

Features:

- Download original GPX
- Copy shareable route URL
- Share using native sharing functionality when available
- Basic download count

The platform should clearly identify the original uploader and encourage proper attribution.

### 3.8 Personal Dashboard

Authenticated users should have a simple dashboard to manage their uploaded routes.

The dashboard should include:

- Total routes uploaded
- Total distance across uploaded routes
- Number of public and private routes
- Total downloads
- Recently uploaded routes
- Route management table
- Add new route button

Keep the dashboard simple and avoid unnecessary analytics.

### 3.9 Administration and Moderation

Create a minimal administration interface for:

- Managing users
- Reviewing reported routes
- Removing inappropriate or unauthorized content
- Managing verified contributor status
- Viewing basic platform statistics

Users should be able to report routes containing misleading information, copyrighted material, or unsafe content.

- GPX Files / Route Assets

- Route Images

## 6. Security, Privacy, and Performance

Because this is a public platform that accepts user-uploaded GPS data, security and privacy are important.

### Security

Implement:

- Secure authentication
- Authorization for route ownership
- File upload validation
- Secure GPX/XML parsing
- Input validation
- Appropriate upload limits
- Rate limiting where necessary
- Protection against common web vulnerabilities

### Privacy

Users should control whether their routes are:

- Public
- Unlisted
- Private

Do not expose private routes through public APIs, search results, or predictable file URLs.

Consider GPS privacy risks, particularly when a route starts or finishes near someone's home.

Evaluate privacy-preserving options such as hiding route endpoints before public sharing.

### Performance

Optimize for:

- Fast route discovery
- Efficient GPX parsing
- Responsive map rendering
- Database query efficiency
- Pagination
- Efficient storage
- Minimal server resource usage

The initial application should be practical to host on a relatively affordable server.
